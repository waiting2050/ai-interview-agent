# 非技术领域包设计：售前 / FDE / 运营

现有三个运行时包是技术岗：`go-backend`、`java-backend`、`ai-agent`。加载器本身与岗位类型无关，只要 manifest 里有 `rubric`、`directions`、`topics`、`lexicon` 就能跑。本文件记录非技术岗位的考点与维度设计，示例 manifest 放在 `docs/domainpacks/examples/`（`solution-presales` / `fde` / `ops-growth`），**不会**被加载，也不出现在下拉列表。

这份文档 + 三份示例 manifest 构成「售前 / 运营引子包」：给非技术岗位的候选人与售前同学一个可直接演示、可复制启用的起点，但不把未审核内容放进评分链路。

## 为什么用示例包而不是直接上线

- 非技术岗位的「正确答案」更依赖公司上下文，先把维度与考点写清楚，再决定是否转成运行时包。
- 示例包放在 `docs/` 下，`embed` 规则 `domainpacks/*/manifest.yaml` 不会扫到，避免未审核内容进入评分链路。
- 评分链路只读本地包，不联网；这与 `design-rationale.md` 的「本地骨架是评分唯一依据」一致。
- 示例仍受加载器校验：`go test ./internal/domain/domainpack` 会逐份解析并试装载，防止文档与 manifest 漂移。

## 售前解决方案

维度（权重合计 1.0）：

| key | 名称 | 权重 | 判定锚点 |
| --- | --- | --- | --- |
| requirement_understanding | 需求理解 | 0.25 | 把客户原话转成可验证的问题、约束与成功标准 |
| solution_expression | 方案表达 | 0.25 | 结论先行，非技术听众能听懂 |
| tradeoff_boundary | 权衡与边界 | 0.20 | 适用条件、不适用场景、成本与替代方案 |
| objection_handling | 异议处理 | 0.20 | 先承认合理部分，再给证据与下一步 |
| credibility | 可信度 | 0.10 | 可核验案例、数据或明确的不确定性 |

考点（每条 3 个 expected_points）：

1. **需求澄清与成功标准**：现状/痛点/角色；可量化验收口径；预算、合规、时间约束。
2. **方案取舍与边界**：为什么选这个架构；不适用场景；降级与替代路径。
3. **POC 设计与验证**：验证假设；样本与指标；失败判定与退出条件。
4. **异议处理**：复述客户判断标准；可验证差异点；承认不确定性与下一步。
5. **交付与预期管理**：里程碑与依赖；验收责任边界；上线后的运营交接。
6. **报价与范围控制**：范围清单；变更成本；不做清单。
7. **安全与合规沟通**：数据边界；权限与审计；第三方依赖风险。
8. **竞品对比**：比较维度；证据来源；不贬低对手的表达。
9. **故事线与演示**：听众分层；一条主线；演示失败预案。
10. **复盘与沉淀**：赢单/丢单归因；可复用资产；下一步动作。

## FDE（Forward Deployed Engineer）

示例：`docs/domainpacks/examples/fde.example.yaml`。

维度：现场排障 0.25 / 集成联调 0.25 / 灰度与回滚 0.20 / 预期管理 0.20 / 可信度 0.10。

考点：

1. 现场问题定位：现象、时间线、最小复现。
2. 日志与指标：先看哪个指标、如何排除噪声。
3. 集成联调：接口契约、鉴权、幂等与重试。
4. 数据迁移与兼容：双写、回滚、数据校验。
5. 灰度发布：分批策略、观察窗口、回滚触发条件。
6. 客户环境差异：网络、权限、版本锁定。
7. 事故沟通：影响面、临时方案、根因与长期修复。
8. 预期管理：能做什么、不能做什么、何时给结论。
9. 交付文档：runbook、值班交接、已知限制。
10. 复盘：可观测性缺口与下一步加固。

## 增长运营

维度：指标口径 0.25 / 实验设计 0.25 / 增长假设 0.20 / 复盘深度 0.20 / 数据可信度 0.10。

考点：

1. 北极星指标与护栏指标：选择依据、反例。
2. 漏斗拆解：分子分母、时间窗口、口径变化。
3. A/B 实验：假设、样本量、最小可检测效应。
4. 分流与干扰：污染、同期事件、多重比较。
5. 留存分析：队列口径、自然增长与活动增量。
6. 归因与相关性：避免把相关当因果。
7. 增长假设：可证伪、连接具体动作。
8. 活动复盘：目标、实际、差异与下一步。
9. 用户分层：分层依据与可执行策略。
10. 数据质量：埋点缺失、重复、延迟。

## 接入方式

把示例复制到 `domainpacks/<id>/manifest.yaml`，改 `id` 与目录一致，补足至少 10 个考点（每考点 3 条 expected_points），启动校验通过后即可在 `/v1/domains` 与会话创建里使用。评分维度、报告维度与前端雷达图都会自动跟随包配置，不需要改代码。

启用前先跑 `go test ./internal/domain/domainpack`，它会逐份解析示例并模拟装载；示例本身只有 2–4 个考点，够验证格式，不够跑完一场面试，正式启用前仍需按上面的考点清单补齐。
